# Мобильный прораб

Java 21, Spring Boot, PostgreSQL, JPA, Flyway; frontend — HTML/CSS/ES-модули.

## Требования

Создание проекта: `docs/specification.docx` (с согласованным изменением AC-03).
Уточнение проекта: `Postanovka_utochnenie_parametrov_proekta-3.docx`, версия 2.5.
Текущее состояние и ограничения: `docs/CODEX_CONTEXT.md`.

## Запуск на macOS

Установить JDK 21 и запустить Docker Desktop. Из корня проекта:

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
docker compose up -d postgres
./gradlew :backend:bootRun
```

В другом терминале из корня проекта:

```bash
python3 frontend/dev_server.py
```

Открыть http://127.0.0.1:5500/. Сервер frontend отключает кэширование модулей для локальной разработки. Backend слушает порт 8080.

После создания проекта адрес содержит `#project=<UUID>`: его можно сохранить для повторного открытия. В проекте нажать «Уточнить параметры проекта» справа от статуса. Из результата создания доступно «Уточнить расчёт».

## Уточнение

Четыре раздела: параметры квартиры, помещения, кухня и техника, балкон и лоджия. Формы сохраняются только по «Продолжить». «Готово» в карточке помещения сохраняет ввод в локальный список. Несохранённый ввод остаётся в памяти страницы, но исчезает при перезагрузке.

После изменения расчётных параметров запускается фоновый пересчёт. Активный бюджет и срок сохраняются до отдельного применения. Незавершённые задания восстанавливаются при запуске backend. Повторное сохранение одинаковых данных не создаёт новый расчёт; повторное применение одного результата идемпотентно.

**Расчёт стоимости демонстрационный.** Пользователь разрешил временные моки вместо отсутствующего модуля стоимости ремонта 1.2.0. `DemoRefinementCalculator` реализует интерфейс `RefinementCalculator`; цены, резерв 10% и нормативы оснащения тестовые. Распределение неизвестной площади реализовано по приложению к постановке, версия `area-norms-2.5`. Расчётные площади не записываются как пользовательские обмеры. Длительность после уточнения не меняется: реального алгоритма пока нет. Исходная оценка остаётся `MockEstimateService`.

Данные уточнения и снимки активного/кандидатного расчёта сохраняются в `project_refinements`, привязанной к `projects`. Схему создаёт Flyway; вручную выполнять INSERT не нужно. После первого входа в уточнение старые операции изменения шагов/пересчёта блокируются, чтобы не заменить активную смету в обход применения.

## Проверки

```bash
./gradlew :backend:test
npm --prefix frontend test
npm --prefix frontend ci
node frontend/node_modules/playwright/cli.js install webkit chromium
npm --prefix frontend run test:browser
```

Браузерные тесты требуют работающие backend, frontend и PostgreSQL. Они создают тестовые проекты в локальной БД, не удаляя существующие данные. Адреса можно переопределить переменными `PRORAB_TEST_API` и `PRORAB_TEST_FRONTEND`.

События уточнения публикуются как `CustomEvent('prorab:analytics')`; параметры содержат только идентификатор проекта и раздел, без адреса и названия. Внешняя система аналитики пока не подключена.


## Вход и регистрация

После запуска откройте веб или Expo и выберите «Нет аккаунта? Зарегистрироваться». Используйте один логин и пароль на обоих устройствах — проекты и доступ будут общими. Логин: 3–40 символов латиницы/цифр/`._-`; пароль: 8–128 символов. Учётки хранятся в PostgreSQL (`accounts`), пароли хешируются. Подробности: [docs/AUTH_IMPLEMENTATION.md](docs/AUTH_IMPLEMENTATION.md). Старые анонимные данные сохранены, их перенос к аккаунту отдельно.
