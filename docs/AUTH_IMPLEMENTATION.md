# Авторизация — 17 октября 2026

По запросу пользователя добавлен простой вход по логину/паролю и регистрация в существующем стиле. Регистрация автоматически выполняет вход. Логин: 3–40 символов, латиница, цифры, точка, дефис и подчёркивание; регистр не учитывается. Пароль: 8–128 символов, сохраняется как введён, без обрезки пробелов.

## Backend

- Feature `auth/{controller,dto,entity,repository,service}`; Flyway V4 создаёт `accounts` и `auth_sessions`.
- Пароль: PBKDF2-HMAC-SHA256, 600000 итераций, отдельная случайная соль. В БД и ответах нет открытого пароля.
- Сессия: случайный 256-битный токен, в БД только SHA-256 токена; срок 30 дней. Повторный вход создаёт независимую сессию. Выход отзывает текущую сессию.
- `POST /api/auth/register`, `POST /api/auth/login`: `{login,password}` → `{userId,login,token,expiresAt}`.
- `GET /api/auth/me`, `POST /api/auth/logout` и все `/api/projects/**` требуют `Authorization: Bearer <token>`.
- `AuthInterceptor` определяет пользователя только по серверной сессии и проверяет владельца для всех маршрутов проекта, включая уточнение. Чужой/старый бесхозный проект возвращает 404. `X-Prorab-User` больше не является удостоверением личности и игнорируется.
- `GET /api/projects` возвращает только проекты аккаунта. Новые проекты, группа A/B, анкета и пробный период привязаны к ID аккаунта, а не устройству. Регистрация сама по себе не назначает группу.
- Базовое ограничение частоты регистрации/входа: 60 попыток в минуту на адрес, в памяти одного процесса. После перезапуска счётчик очищается; это не распределённый механизм защиты.

## Клиенты

Веб показывает экран входа/регистрации, затем список проектов; выход доступен в верхней панели. Expo показывает такой же экран по смыслу и стилю; выход — на экране «Мои проекты». Кнопка отправки неактивна до корректного заполнения и во время запроса. Ошибка оставляет введённые поля. Пароль скрыт при вводе и не сохраняется на устройстве.

На iPhone токен хранится через Expo SecureStore; в вебе — в localStorage. При выходе очищаются сеансовые черновики клиента. В Expo удалена прежняя зависимость списка проектов от локальной истории UUID. Сессии на разных устройствах независимы, аккаунт и проекты общие.

## Границы

- Старые анонимные проекты и данные онбординга не удалены, но автоматически к новым аккаунтам не присваиваются: прежний UUID устройства не доказывает владение после введения авторизации. Перенос конкретных старых данных нужно выполнять отдельно с явным определением владельца. Старые ссылки не открывают чужие данные.
- Нет восстановления/изменения пароля, email/SMS, социальных входов и платежей. Это не входит в текущий простой сценарий.
- Локальный запуск использует HTTP. Для публикации нужен HTTPS; текущий web-токен в localStorage доступен JavaScript. Не выдавать локальную конфигурацию за готовую публичную эксплуатацию.
- Legacy бизнес-тесты используют подменённый interceptor для старых fixtures; `AuthApiTest` отдельно проверяет настоящую цепочку авторизации, хеширование, срок/отзыв сессий и владение проектами. Браузерные тесты работают с настоящими аккаунтами и API.


## Смена пароля — 28.10.2026

WEB/Expo: меню пользователя → Изменить пароль → Новый пароль → Сохранить.
Старый пароль не требуется по запросу владельца. PUT /api/auth/password принимает
{newPassword}; аккаунт определяется только из Bearer-сеанса. 8–128 символов,
пустой/пробельный пароль запрещён. PBKDF2, optimistic @Version (V16), атомарный
отзыв остальных сеансов; текущий остаётся до исходной даты истечения.
При ошибке форма сохраняет введённое значение только в памяти до закрытия.
