# Онбординг и доступ — 16 октября 2026

**Обновление 17 октября:** идентификация устройства заменена аккаунтами. Все API ниже требуют Bearer-токен; прежний X-Prorab-User не принимается как авторизация. См. `AUTH_IMPLEMENTATION.md`. Исторические ограничения анонимной версии ниже сохранены для контекста.

Источник: `onboarding.docx`. DOCX не изменён. Ниже — явно согласованные пользователем уточнения, имеющие приоритет над противоречиями документа.

## Согласованные правила

- При первом сохранении проекта пользователь получает A или B по очереди: A → B → A → B. Ответы анкеты не влияют на группу.
- Если к первой классификации в серверной истории уже есть завершённый проект, назначается B, анкета пропускается. Такой пользователь не расходует очередь новых пользователей; общий размер групп поэтому может отличаться.
- Группа закреплена за пользователем; новые проекты не меняют её. Появление завершённого проекта после назначения не вызывает скрытую переклассификацию.
- Для A предлагается 7 дней полной версии. Отсчёт начинается только по «Начать 7 дней бесплатно». «Позже» не запускает срок. Повторное подтверждение не продлевает и не возобновляет его.
- Для B и A после окончания пробного периода используется экран подписки. Калькулятор и уточнение сметы остаются доступны. Цена и платёжный сервис не согласованы: кнопка оформления отключена, причина видна пользователю. Списаний и фиктивного подключения подписки нет.

## Реализация

Веб и Expo: CP-01 → анкета → предложение доступа → CP-02. Анкета не добавляет шаг к счётчику пяти шагов квартиры. Все три ответа обязательны, включая допустимый ответ `false`. Возврат к CP-01 сохраняет выбор в памяти сеанса; повторное сохранение CP-01 обновляет существующий проект. Ошибка отправки оставляет ввод. Сохранённая анкета больше не спрашивается и не перезаписывается.

Предложение не прерывает каждое повторное открытие проекта. Оно доступно повторно по «Доступ к полной версии» в проекте, а в Expo также в списке проектов. После активации показывается дата и время окончания. При следующем открытии состояние вычисляется сервером.

Backend feature `onboarding/{controller,dto,entity,repository,service}`. Миграция V3 создаёт `user_access`, `access_allocation`, `onboarding_events` и принадлежность новых проектов `projects.owner_id`. Сохранение проекта и первая классификация — одна транзакция. Блокировка общей строки очереди сериализует назначения, включая одновременные запросы одного нового пользователя. Неуспешная транзакция не расходует очередь. Существующие проекты не присваиваются новому пользователю по одному лишь открытию ссылки.

Анкета и пробный период сохраняются под блокировкой записи пользователя с JPA-версией. Ответы после успешного сохранения неизменны; повтор тех же ответов идемпотентен. Начало и конец пробного периода определяет backend (ровно 7 × 24 часа); клиентские часы не дают доступ. События просмотра анкеты, отправки, назначения группы, предложения подписки и активации пробного доступа и технической ошибки назначения сохраняются в БД без названия и адреса проекта. Внешняя аналитическая система не подключена.

API, заголовок `X-Prorab-User: <UUID>`:

- `POST /api/projects/draft` — создаёт проект и при наличии заголовка классифицирует пользователя.
- `GET /api/projects/access` — DTO текущего доступа.
- `POST /api/projects/access/view` — первое отображение анкеты.
- `POST /api/projects/access/answers` — три ответа + `questionnaireVersion: "1"`.
- `POST /api/projects/access/offer` — отображение предложения доступа.
- `POST /api/projects/access/trial` — явное согласие на запуск пробного периода.

## Ограничения

- Полноценной авторизации пока нет. Стабильный анонимный UUID хранится в localStorage веба / AsyncStorage Expo. Это временная идентификация устройства, не защищённый аккаунт: браузер и телефон считаются разными пользователями, очистка хранилища создаёт нового. Перед коммерческим запуском нужна аутентификация и привязка серверного доступа к подтверждённому аккаунту; нельзя считать UUID-заголовок полноценной защитой подписки.
- `COMPLETED` добавлен как серверный статус для проверки истории. Пользовательского сценария завершения ремонта пока нет. `ACTIVE`, `completedStep=5` и ответ анкеты «Завершён» не считаются завершённым проектом. Старые проекты без владельца не используются как история случайного нового пользователя.
- Платёжного провайдера, цены, покупок и восстановления подписки нет. Сервер может отражать `subscription_status`, но публичного API фиктивной активации не добавлено.
- План работ и оба трекера по-прежнему не реализованы; предложение полной версии не означает их готовность. Когда появятся платные API, они должны проверять доступ на сервере, а не только скрывать кнопки.
- Несохранённые ответы переживают переходы между экранами, но не закрытие приложения/перезагрузку. Сохранённые ответы, группа и пробный период находятся в PostgreSQL.
- Идемпотентность назначения и пробного доступа есть; общая идемпотентность создания самого черновика при потерянном HTTP-ответе остаётся отдельной задачей.

## Проверки

`AccessApiTest`: назначение при сохранении, независимость от ответов, повторные проекты, валидация и неизменность анкеты, повторные запросы, явное подтверждение, срок 7 дней, запрет перезапуска после истечения, запрет пробного периода B, завершённая история, конкурентное назначение одному пользователю.

Веб: тесты формы и экрана доступа, браузерные сценарии WebKit/Chromium с возвратом, ошибкой сети, обеими группами, активацией и перезагрузкой. Expo: прежний полный браузерный сценарий дополнен анкетой и предложением; прокси проверяет передачу анонимного ID. Физический iPhone отдельно не проверен.
