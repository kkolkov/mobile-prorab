## Количество комнат вместо кухонь — 20 октября 2026

По указанию пользователя CP-04 в вебе и Expo теперь запрашивает «Количество
комнат» (жилых, без кухни и санузлов), по умолчанию 1, допустимо 1–20.
Сохраняется отдельное roomsCount; кухни не переименованы в данные комнат.
Миграция V6 добавляет nullable rooms_count: для старых проектов значение
не выдумывается из kitchens_count. Старые API-запросы с kitchensCount
поддерживаются. CP-06 показывает комнаты; при неизвестном числе — прочерк.
JSON-дроби для целочисленных полей отклоняются, а не молча усекаются.
В демонстрационном сроке используется roomsCount, для legacy — прежний fallback.

При первом открытии уточнения заданное количество создаёт жилые комнаты и
фиксируется как ручной выбор; кухня остаётся отдельной, санузлы отдельно.
Сохранение состава помещений обновляет roomsCount. Для старых проектов без
roomsCount сохраняются прежние рекомендации по площади и существующие комнаты.
35 backend-тестов и четыре UI-сценария в Chromium/WebKit для веба/Expo Web
прошли: счётчик, сохранение только по Продолжить, повторное открытие, кухня=1.
Typecheck/lint прошли. Полный мобильный мастер и уточнение проверены
с явным выбором трёх комнат. Backend локально перезапущен с V6.
Render и APK с этим изменением пока не обновлены.

## Переименование проекта — 19 октября 2026

В списке «Мои проекты» веба и Expo у каждого проекта добавлена кнопка
«Переименовать». Форма с Сохранить/Отмена, непустое имя до 100 символов.
PUT /api/projects/{id}/name принимает name/version; проверяет владельца,
валидирует ввод и optimistic lock. Меняет только имя, nameSource=user,
updatedAt и версию; смета, статус и шаг не сбрасываются. Работает и для
черновиков, и для активных проектов, независимо от уточнения.
При сетевой ошибке ввод сохранён. При 409 необходимо загрузить актуальную
версию, затем отдельно подтвердить сохранение своего имени.
Проверены 34 backend-теста, frontend unit, mobile typecheck/lint и четыре
сквозных сценария Chromium/WebKit для веба/Expo Web с PostgreSQL: сохранение,
перезагрузка, отмена, пустое имя, ошибка сети, конфликт и явный повтор.
Локальный backend перезапущен. Render и APK с переименованием не обновлены.

## Изменение порядка создания — 19 октября 2026

По явному указанию пользователя: каждый новый проект начинается с «Расскажите
о себе», затем CP-01 «Об объекте», затем сразу CP-02. Экраны предложений полной
версии и входы в них удалены из веба/Expo. Старый мобильный /access перенаправляет
на указанный шаг или домой. CP-03 называется «Желаемый результат ремонта»,
блок «Что входит» удалён. Это согласованное изменение прежних требований.

Анкета до CP-01 хранится в памяти; возврат сохраняет её и поля квартиры.
POST draft принимает валидируемую questionnaire, сохраняет ответы в projects
(миграция V5) в одной транзакции с черновиком. Для совместимости старые запросы
без questionnaire принимаются. Для первого проекта заполняется также прежняя
анкета аккаунта; ответы последующих проектов не меняют её или группу A/B.
Группа по-прежнему назначается при сохранении проекта; пробный доступ сам
не запускается. Старые черновики открываются сразу на незавершённом шаге.

Проверены backend-тесты и новый сценарий в Chromium/WebKit для веба и Expo Web
с PostgreSQL, включая отказ сети и повтор, возврат, отсутствие раннего черновика.
На Render изменения пока не опубликованы; APK с этим порядком ещё не собран.

## Согласие при регистрации — 19 октября 2026

В вебе и Expo форма регистрации содержит выключенный по умолчанию чекбокс
согласия и одну ссылку на политику. Политика пока содержит LOREM IPSUM по
указанию пользователя; в Expo открывается полноэкранным Modal с кнопкой Назад
и обработкой системного возврата. Возврат сохраняет ввод и не включает согласие.
Обычный вход не требует галочки. Клиенты передают `privacyAccepted: true` при
регистрации; backend отклоняет отсутствие, null и false до создания аккаунта.
Отдельный журнал согласий/юридический текст не реализованы. Новое серверное
правило требует обновлённого клиента для регистрации, вход старых клиентов сохранён.
Backend-тесты, 11 веб-unit, 10 мобильных unit, typecheck/lint и 4 проверки
политики в Chromium/WebKit (веб и Expo Web) прошли. Проверки интерфейса используют
подменённый ответ регистрации; серверное правило проверено отдельно в AuthApiTest.
Изменения backend/веб пока локальные, на Render не опубликованы.

## Реализовано

### Создание проекта

Исправлены JPA mapping `area_m2`, lowercase enum JSON, возврат версии после flush, зависшее состояние «Сохранение…», оформление disabled-кнопок, выбор `false` перепланировки. Добавлены unit/API/persistence-тесты. CP-01–06 работают с исходным `MockEstimateService`; стоимость и длительность тестовые и подписаны соответствующим образом.

Активация разрешена после пяти завершённых шагов независимо от успеха расчёта. Вход в уточнение из CP-06 активирует завершённый проект. Ссылка `#project=<UUID>` позволяет повторно открыть существующий проект; `&refinement=1` открывает уточнение.

### Уточнение

Кнопка «Уточнить параметры проекта» расположена справа от статуса «Планирование». Четыре раздела: квартира, помещения, кухня/техника, балкон/лоджия. Формы и UI находятся в `frontend/js/refinement/`.

Сохранение только по «Продолжить»; карточка помещения по «Готово» меняет локальный список. Несохранённые разделы удерживаются в памяти вкладки (в том числе при возврате в проект); перезагрузка их очищает. Конфликт сохраняет локальный ввод и предлагает загрузить актуальную версию; сохранение поверх неё требует отдельного явного нажатия. Флажки оборудования/работ различают null (норматив) и false (отказ).

Backend feature: `refinement/{controller,dto,entity,repository,model,service}`. Flyway V2 создаёт `project_refinements`: версионированный документ пользовательских параметров с устойчивыми UUID комнат, оборудованием по UUID кухни, флагами уточнения, ревизией, состоянием расчёта и отдельными снимками активной/кандидатной сметы. REST возвращает DTO, не entity. Подготовка данных для старых проектов производится перед первым доступом к форме, под блокировкой проекта, идемпотентно; открытие не отмечает раздел уточнённым.

`AreaAllocator` реализует нормы распределения неизвестных площадей из приложения (версия `area-norms-2.5`): минимумы, типовые/максимальные площади, условный коридор, остаток сухой площади, округление по дробным остаткам и UUID. Расчётные значения не подставляются в пользовательские поля. Превышение сверх допуска блокирует сохранение; нехватка площади допускает сохранение, но не полный расчёт и применение.

После изменённых расчётных параметров запускается асинхронный пересчёт полного проекта. Одинаковые данные не запускают повтор. Поздние/повторные результаты не заменяют новый результат; незавершённые задания восстанавливаются при старте backend. Применение проверяет текущую ревизию и версию проекта; повтор одного применения идемпотентен. Старая смета сохраняется до применения. Старые операции шагов и старого пересчёта блокируются после подготовки уточнения, чтобы не обойти эту границу.

`DemoRefinementCalculator` — временный провайдер `RefinementCalculator`: тестовые цены, резерв 10%, нормативы оснащения. Учитывает типы помещений, наследование/исключения отделки, ручные работы, состав кухонной техники, отказы, раздельные балкон/лоджию; встроенная духовка и внешние помещения не добавляются дважды. Новую длительность не выдаёт, прежний срок сохраняется.

Сравнение показывает диапазоны, ожидаемые суммы, резерв, рублёвую разницу, ремонт и кухню, внешние помещения внутри ремонта, версии/причины/допущения. У исходного legacy mock нет разбивки ремонта/кухни: показано «Нет данных», не выдумана ретроспективная разбивка. Для сопоставления с legacy ожидаемое — середина диапазона, резерв 10%; это явно отмечено как допущение.

События аналитики передаются через `CustomEvent('prorab:analytics')` без адреса и названия; первое изменённое сохранение отличается от открытия/подготовки/no-op. Внешняя аналитическая система пока не подключена.

## Осталось / ограничения

- Модуль стоимости ремонта 1.2.0, реальные цены, поддерживаемые реальные материалы/геометрия и алгоритм длительности не предоставлены. Демо должен быть заменён через интерфейс; реальный расчёт не считается завершённым.
- Исходные старые пробелы вне этой итерации: в вебе главный экран со списком черновиков отсутствует; API draft не имеет ключа идемпотентности. Не считать эти пункты выполненными.
- Существующие план работ, трекеры расходов и ремонта отсутствуют; на DB-01 это обозначено. Их разработка не входила в эти постановки.
- При разработке всегда читать фактический код: прежний контекст содержал устаревший baseline. Не менять постановки без явного согласования.
