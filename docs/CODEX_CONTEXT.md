## Реализовано

### Создание проекта

Исправлены JPA mapping `area_m2`, lowercase enum JSON, возврат версии после flush, зависшее состояние «Сохранение…», оформление disabled-кнопок, выбор `false` перепланировки. Добавлены unit/API/persistence-тесты. CP-01–06 работают с исходным `MockEstimateService`; стоимость и длительность тестовые и подписаны соответствующим образом.

Активация разрешена после пяти завершённых шагов независимо от успеха расчёта. Вход в уточнение из CP-06 активирует завершённый проект. Ссылка `#project=<UUID>` позволяет повторно открыть существующий проект; `&refinement=1` открывает уточнение.

### Уточнение

Кнопка «Уточнить параметры проекта» расположена справа от статуса «Планирование». Четыре раздела: квартира, помещения, кухня/техника, балкон/лоджия. Формы и UI находятся в `frontend/js/refinement/`.

Сохранение только по «Продолжить»; карточка помещения по «Готово» меняет локальный список. Несохранённые разделы удерживаются в памяти вкладки (в том числе при возврате в проект); перезагрузка их очищает. Конфликт сохраняет локальный ввод и предлагает загрузить актуальную версию; сохранение поверх неё требует отдельного явного нажатия. Флажки оборудования/работ различают null (норматив) и false (отказ).

Backend feature: `refinement/{controller,dto,entity,repository,model,service}`. Flyway V2 создаёт `project_refinements`: версионированный документ пользовательских параметров с устойчивыми UUID комнат, оборудованием по UUID кухни, флагами уточнения, ревизией, состоянием расчёта и отдельными снимками активной/кандидатной сметы. REST возвращает DTO, не entity. Подготовка данных для старых проектов производится перед первым доступом к форме, под блокировкой проекта, идемпотентно; открытие не отмечает раздел уточнённым.

`AreaAllocator` реализует нормы распределения неизвестных площадей из приложения (версия `area-norms-2.5`): минимумы, типовые/максимальные площади, условный коридор, остаток сухой площади, округление по дробным остаткам и UUID. Расчётные значения не подставляются в пользовательские поля. Превышение сверх допуска блокирует сохранение; нехватка площади допускает сохранение, но не полный расчёт и применение.

После изменённых расчётных параметров запускается асинхронный пересчёт полного проекта. Одинаковые данные не запускают повтор. Поздние/повторные результаты не заменяют новый результат; незавершённые задания восстанавливаются при старте backend. Применение проверяет текущую ревизию и версию проекта; повтор одного применения идемпотентен. Старая смета сохраняется до применения. Старые операции шагов и старого пересчёта блокируются после подготовки уточнения, чтобы не обойти эту границу.

`DemoRefinementCalculator` — временный провайдер `RefinementCalculator`: тестовые цены, резерв 10%, нормативы оснащения. Учитывает типы помещений, наследование/исключения отделки, ручные работы, состав кухонной техники, отказы, раздельные балкон/лоджию; встроенная духовка и внешние помещения не добавляются дважды. Новую длительность не выдаёт, прежний срок сохраняется.

Сравнение показывает диапазоны, ожидаемые суммы, резерв, рублёвую разницу, ремонт и кухню, внешние помещения внутри ремонта, версии/причины/допущения. У исходного legacy mock нет разбивки ремонта/кухни: показано «Нет данных», не выдумана ретроспективная разбивка. Для сопоставления с legacy ожидаемое — середина диапазона, резерв 10%; это явно отмечено как допущение.

События аналитики передаются через `CustomEvent('prorab:analytics')` без адреса и названия; первое изменённое сохранение отличается от открытия/подготовки/no-op. Внешняя аналитическая система пока не подключена.
