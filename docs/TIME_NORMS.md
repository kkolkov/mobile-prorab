# Сроки из Сроки.xlsx — 28 октября 2026

Сроки подключаются вместе с новым справочником цен. Пользователь подтвердил
совместную публикацию веба и выпуск Android APK после проверок.

## Что предоставлено

16 норм трудоёмкости из столбца D листа «Работы». Нормы одинаковы во всех
16 городах, поэтому усреднять их повторно не требуется. Столбец C содержит
округлённые рабочие дни для двух человек, а не календарный срок ремонта.
Берём точные человеко-часы: например, штукатурка стен — 74,00 чел.-ч / 100 м²,
ламинат — 22,55, настенная плитка — 115,26, напольная — 119,78.

Источники норм и ограничения взяты из файла, самостоятельная проверка
соответствия редакции ГЭСН не заявляется. Это нормы операций, не реальные сроки
конкретной бригады. Сушка, доставка, организация рабочего места исключены файлом.

## Связь со сметой и графиком

1. Берём только строки работ `average.work.*` из рассчитанной сметы.
   Материал той же операции не добавляет время повторно.
2. Объёмы одной операции суммируем по всему проекту, включая внешние помещения.
3. Человеко-часы = м² × норма / 100. Цена, класс и коэффициенты стоимости не
   множат трудозатраты; явные исключения/частичные объёмы уже отражены в м².
4. По фазе складываем человеко-часы без промежуточного округления.
5. Для двух человек по 8 часов рабочие дни = часы / 16. Ориентировочные календарные
   дни = ceil(рабочие дни × 7/5). Принята условная пятидневка: праздники, фактический
   день недели начала и параллельные бригады не моделируются. По дням конкретного
   производственного календаря эта оценка не претендует на точность.
6. Сохраняем четыре существующих фазы, их порядок и постоянные ID. Нормированные
   подготовка/стяжка относятся к черновой фазе; отделка — к чистовой.
7. Если в фазе есть работа без нормы, срок = максимум рассчитанной части и прежнего
   ориентира фазы. Это нижний ориентир смешанного расчёта, не сумма всех нормативных
   затрат. Для черновой фазы прежний ориентир ceil(площадь × 0,2 + 5), чистовой —
   ceil(площадь × 0,3 + 7), монтажа/уборки — 4 дня. Не приписываем этим числам ГЭСН.
8. При подготовке сохранена отдельная пауза 8 календарных дней как допущение
   прежней модели. Она **не подтверждает готовность стяжки к покрытию**: фактическую
   сушку/набор прочности определяют технология и условия. Файл таких сроков не даёт.
9. Сумма фаз — нижняя оценка, верхняя = ceil(нижняя × 1,2), прежний оценочный запас.

Нормативная часть, источники, версия и пояснения сохраняются в `TimePlan` внутри
снимка сметы (`phases-2-<hash>`). В детализации WEB/Expo есть таблица трудозатрат.
Предварительная оценка и уточнение используют один планировщик. Новый график
берёт сохранённые длительности фаз из применённой сметы.

## БД и админка

Flyway V14: таблица `time_norms`, 16 норм. Импорт воспроизводится скриптом
`scripts/import_time_workbook.py`; исходный XLSX не требуется серверу после сборки.
Данные для миграции: `pricing/time-norms-2026-10-28.json`.

`/porabadmin/time-norms.html` — просмотр и изменение человеко-часов, источника,
даты. Единица фиксирована: человеко-часы на 100 м². REST
`GET /api/porabadmin/time-norms`, `PUT /api/porabadmin/time-norms/{code}`.
Проверяются положительное число, точность, дата и версия строки. Конфликт
не перезаписывает ввод. Доступ публичный в рамках существующей публичной админки.
Удаление норм интерфейсом не предлагается. Если используемая норма отсутствует
в БД, расчёт завершится ошибкой, а не назначит нулевое время.

## Старые проекты

Старые TimePlan без новых полей читаются без изменений. Новая норма влияет только
на следующий расчёт. Пересчитанная смета сначала кандидатная; применение не
переписывает ранее начатый график или расходы. Синхронизация финансового плана
сохраняет фактические даты, завершённые этапы и траты. Новый график получит новые
сроки только если ещё не был начат и его бюджет обновлён до новой сметы.
