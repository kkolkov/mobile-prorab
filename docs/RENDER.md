# Демо для коллег на Render

Веб и REST API размещаются одним Docker Web Service. Spring Boot раздаёт только
`frontend/index.html`, `css/` и `js/`, включённые в JAR при сборке Gradle.
Браузер обращается к `/api` на том же HTTPS-адресе. Локальный запуск на 5500
сохраняет прежнее подключение к backend:8080. Expo не требуется для веб-демо.

## Первое размещение

1. Загрузить исходники в приватный GitHub-репозиторий. Локальные `.env`,
   артефакты сборок, node_modules и личный дневник не загружать.
2. В Render выбрать **New → Blueprint**, подключить GitHub и выбрать репозиторий.
3. Использовать `render.yaml` из корня. Он создаёт Web Service `mobile-prorab`
   и PostgreSQL `mobile-prorab-db` в одном регионе (Frankfurt).
4. Проверить предложенные ресурсы: в шаблоне у обоих указан план **free**.
   Пароль базы генерирует Render и передаёт приложению через переменные окружения.
   Публичные подключения к базе отключены (`ipAllowList: []`).
5. После успешного развёртывания открыть URL Web Service `https://…onrender.com`.
   Зарегистрироваться, создать проект, перезагрузить страницу и проверить
   сохранение проекта. Затем передать ссылку коллегам.

На Render создаётся новая база. Локальные аккаунты и проекты автоматически туда
не переносятся. Миграции Flyway выполняются при старте. Данные сохраняются в
PostgreSQL отдельно от контейнера приложения.

## Ограничения бесплатного демо

- Web Service засыпает после 15 минут без запросов; первое открытие может занять
  около минуты.
- Бесплатная PostgreSQL действует 30 дней. До истечения срока нужно выбрать
  платный план либо экспортировать нужные данные. Это временный стенд.
- Расчёт остаётся демонстрационным; размещение не добавляет реальную оплату
  или отсутствующие платные инструменты.
- HTTPS завершает Render; приложение слушает предоставленный `PORT`.
- Проверка здоровья `/` подтверждает запуск Spring и наличие веб-страницы;
  это не постоянная отдельная проверка доступности БД.

## Сборка локально

```sh
docker build -t mobile-prorab:render .
```

В сборку входят backend-тесты. Контейнер работает от непривилегированного
пользователя, требует `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
По умолчанию слушает 8080; `PORT` имеет приоритет над `SERVER_PORT`.

Проверка работающего развёртывания (создаёт тестовый аккаунт и проект):

```sh
PRORAB_DEPLOY_URL=http://127.0.0.1:18080 node --test frontend/tests/deployment/smoke.mjs
```

Требуются установленные dev-зависимости frontend и браузер Chromium Playwright.
Проверяются регистрация через UI, запросы к API на том же адресе, сохранение
проекта после перезагрузки, отказ API без авторизации и недоступность
служебных файлов frontend.

Документация Render:
- https://render.com/docs/blueprint-spec
- https://render.com/docs/docker
- https://render.com/docs/free

## Текущий CI/CD

Репозиторий: `kkolkov/mobile-prorab`, ветка `main`.
Push в подключённую ветку запускает Render Auto-Deploy, если он включён
в настройках сервиса. Dockerfile выполняет backend-тесты перед созданием JAR.
Отдельного workflow GitHub Actions в репозитории пока нет; frontend и Expo
проверяются локально. APK собирается отдельно в Expo EAS, push на Render
не обновляет установленное мобильное приложение.

Проверка деплоя `frontend/tests/deployment/smoke.mjs` охватывает согласие при
регистрации, анкету до объекта, создание проекта, количество комнат, формат
срока, переименование и восстановление после перезагрузки. Она создаёт
один тестовый аккаунт и проект на проверяемом стенде.
